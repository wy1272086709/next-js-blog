#### 项目总结
##### 项目中遇到的几个性能问题
1. 点赞的场景，我使用了Redis来存储点赞信息，避免了数据库的频繁操作，但没有想到，Redis和应用不在同一个区域部署，导致Redis超时了，然后需要处理Redis和数据库之间的同步，性能反而下降了。

**查询页面流程（读操作）：**

```mermaid
flowchart TD
    Start([用户访问文章页面]) --> Q1[应用向 Redis 查询点赞信息]
    Q1 --> Check{Redis 中是否命中?}
    Check -->|命中缓存| Return[直接返回缓存数据]
    Check -->|未命中| Q2[向数据库查询点赞信息]
    Q2 --> Q3[将查询结果写入 Redis 缓存]
    Q3 --> Return
    Return --> End([渲染页面展示给用户])

    classDef redis fill:#ffcccc,stroke:#c0392b,color:#000
    classDef db fill:#ccffcc,stroke:#27ae60,color:#000
    class Q1,Q3 redis
    class Q2 db
```

**点赞操作流程（写操作）：**

```mermaid
flowchart TD
    Start([用户点击点赞按钮]) --> W1[更新 Redis 中的点赞信息]
    W1 --> W2[更新数据库中的点赞信息]
    W2 --> Check{数据库更新是否成功?}
    Check -->|成功| OK[返回点赞成功]
    Check -->|失败| Rollback[回滚 Redis 中的点赞信息]
    Rollback --> Fail([返回点赞失败])
    OK --> End([刷新页面])

    classDef redis fill:#ffcccc,stroke:#c0392b,color:#000
    classDef db fill:#ccffcc,stroke:#27ae60,color:#000
    class W1,Rollback redis
    class W2 db
```

> 💡 由于 Redis 与应用不在同一区域，每一次查询（未命中时）和每一次点赞都需要跨区域访问 Redis，网络往返耗时叠加后导致整体性能下降。
